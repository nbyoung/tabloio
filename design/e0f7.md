# Design e0f7: Text renderers

This task delivers the `--text` format of all ten views as one writer, `internal/render/text`, over the `doc.Doc` that every builder already returns ([design e3ed](e3ed.md#a-second-output-form), decision 2). It adds no builder and no view. Seven choices shape it. The writer removes the emoji selector U+FE0F after a narrow symbol unless `--selector keep` asks otherwise, which is tablotui's accepted rule for a terminal that reports nothing (D1). It counts cells with the East Asian Width tables of `golang.org/x/text`, the task's one dependency (D2). A table that does not fit the width first gives up the padding of its centred columns, then wraps its text columns, then stacks each row as a record, so no line runs past the width (D3). The width comes from `--width <n>`, 80 by default, and the command reads neither `COLUMNS` nor a terminal (D4). The output is plain: no escape sequence, emphasis between asterisks, a link's target in angle brackets (D5). The closing command carries `--text`, so that it reproduces the rendering (D6). The command's text table takes its own function type, and the brief keeps its one renderer under both formats (D7).

## The model

### Packages and flow

| Path                         | Change                                                                                         |
|------------------------------|------------------------------------------------------------------------------------------------|
| `internal/render/text/`      | New: `text.go`, `width.go`, `table.go`, as [`model.md`](e0f7/model.md) holds them, and their tests |
| `internal/render/`           | `Options` gains `Text`; `Render` gains one case; `command` appends the text flags (D6)          |
| `internal/render/testdata/`  | One text golden beside each Markdown golden, and four variants                                  |
| `internal/cli/`              | `--width` and `--selector` join the vocabulary; the `text` table fills (D7)                     |

Data flows as before: `view.Decode`, the view's builder, a writer. The text writer sees a `doc.Doc` and two options, and nothing of a view. It holds no state and reads no environment, file, clock or terminal.

```go
// Package text writes a doc.Doc as plain Unicode text at a width in cells.
package text

// Selector is the policy for U+FE0F, the variation selector that asks for
// the emoji form of a symbol, where it follows a code point one cell wide.
type Selector int

const (
	Strip Selector = iota // remove the selector: the symbol takes one cell
	Keep                  // keep the selector and count the pair as two cells
)

// ParseSelector reads "strip" or "keep"; String returns the same words.
func ParseSelector(s string) (Selector, error)
func (s Selector) String() string

const (
	DefaultWidth = 80 // what Options.Width 0 means
	MinWidth     = 20 // a smaller Options.Width counts as this
)

// Options holds the width and the selector policy. The zero value is 80
// cells and Strip.
type Options struct {
	Width    int
	Selector Selector
}

// Write prints d to w in one call to w.Write; a write error passes through
// unwrapped, and an empty document writes nothing.
func Write(w io.Writer, d doc.Doc, o Options) error
```

```go
// In package render. Options gains one field, which Markdown ignores.
type Options struct {
	Format Format
	Level  view.Level
	Stamp  bool
	Unfold bool
	Links  Links
	Text   text.Options // the width and the selector policy of the text format
}
```

`Render` builds the document as today and hands it to `text.Write(w, d, o.Text)` when `o.Format` is `Text`, to `markdown.Write` otherwise. `buildDoc` returns `ErrFormat` for a format that is neither. `Write` returns no error of its own, so the errors of `Render` stay `ErrFormat`, `ErrLevel`, `ErrView` and a write error.

**The output.** Blocks print with one blank line between them; lines end in `\n`; no line ends in a space; the output ends in one newline. It holds no control character but `\n`, so no escape sequence, and no byte order mark. No line is wider than the width but a line of a `Pre`, and a line of a list nested so deep that fewer than 16 cells remain for it. The same document and options give the same bytes (R15).

### The measure (D1, D2)

One function gives the cells of a code point:

| Cells | Code points                                                                                                 |
|-------|-------------------------------------------------------------------------------------------------------------|
| 0     | U+0000 to U+001F and U+007F to U+009F; the categories `Mn`, `Me` and `Cf` of the standard `unicode` package |
| 2     | East Asian Width `W` or `F`, by `width.LookupRune(r).Kind()` of `golang.org/x/text/width`                    |
| 1     | Every other, the East Asian Ambiguous ones included: `—`, `…`, `·`, `×`, `→`, the box characters            |

The cells of a string are the sum over its code points. Under `Keep`, a U+FE0F that follows a one-cell code point counts one cell, so `⚙️` takes two. Under `Strip`, the writer removes each U+FE0F that follows a one-cell code point before it measures or prints, so `⚙️` prints as U+2699 and takes one; a U+FE0F after a two-cell code point stays, since it changes no width. [`widths.tsv`](e0f7/widths.tsv) lists the result for every symbol of SYNTAX.md's gate sets, the marks, the signs the builders write and the box characters.

The policy applies to every span, `Text` and `Code` as well as `Symbol`: a title that holds `⚙️` breaks a border as a gate symbol does. It does not apply to a `Pre`, which prints as given. This departs in one word from design e3ed, which expects the policy on "symbols alone".

`Strip` is the default because it is the branch of tablotui's accepted rule (`679b`, decision 5) that applies when no terminal reports how it clusters: "measure by code point and remove U+FE0F after a narrow base". tabloio probes no terminal ([design 5ca9](5ca9.md), A14), so it takes that branch unless the user states the other with `--selector keep`. The prototype's third policy, which keeps the selector and counts one cell, is dropped: it describes a terminal that draws a glyph wider than the cell it reserves, and no rule of the family serves it.

The measure counts code points, not grapheme clusters. A sequence joined by U+200D, a flag and a skin tone count the sum of their parts, which is what a terminal without clustering draws and more than a clustering one draws. No symbol of the method's sets is such a sequence.

### Spans

A run of spans prints as one line of plain text, trimmed at both ends.

| Span     | Prints                                                                                                        |
|----------|---------------------------------------------------------------------------------------------------------------|
| `Text`   | As given: no escaping. A run of white space, a line break included, becomes one space                          |
| `Code`   | As `Text`: no backticks                                                                                        |
| `Symbol` | As given, under the selector policy                                                                            |
| `Strong` | Its content between asterisks, `*Sensor node*`; nothing when the content is empty                              |
| `Link`   | Its text, a space and the URL in angle brackets, `Proposed views <PLAN.md#views>`; the text alone when it equals the URL or the URL is empty |

After that, each remaining control character (category `Cc`) prints as U+FFFD, so a title or a commit subject cannot send an escape sequence to a terminal. `Strong` keeps its mark because a list view shows the person in view in bold (R5), and that is content; the grid's brackets pass through as text.

### Blocks

- **Heading.** The text, wrapped at the width, then a rule as wide as its widest line: `═` for level 1, `─` for level 2, `·` for a deeper level.
- **Para.** The text, wrapped at the width.
- **List.** Each item starts `- `, or `<n>. ` in an ordered list. Its further lines and its nested blocks indent by the marker's width, and wrap at the width less that indent, never at less than 16 cells. An item with no text prints its marker alone.
- **Pre.** Each line as given after four spaces, without its trailing spaces; a tab prints as a space and any other control character as U+FFFD. An empty line stays empty. No line wraps: a command stays whole for a reader who copies it, and a tree keeps its columns.
- **Wrapping.** Lines fill greedily with words, which single spaces separate. A word wider than the line breaks between units; a unit is a code point with a width, the zero-width code points after it, and whatever U+200D joins to it. No hyphen marks a break.

### The table (D3)

A cell is its spans as one line and an indent of two cells for each step of `Cell.Indent`. Each column has a natural width, the widest cell with its indent, the header included, and a floor, the widest word of any cell with its indent, where a word counts at most 24 cells. So an id, a date, an email and a model identifier never break inside a box. A row shorter than the table gets empty cells; a column with no `Align` is left-aligned.

The table takes the first of three forms that fits the width:

1. **The padded box.** Every column at its natural width, one space each side of every cell. It fits when the natural widths, two cells of padding for each column and one cell for each bar sum to the width or less. The table is as wide as its content; it never stretches.
2. **The tight box.** Centred columns lose their padding; the others keep it. It fits when the floors sum to the width or less with the bars and the remaining padding. The columns start at their natural widths, and while the table is too wide the widest column still above its floor narrows by one cell, the leftmost on a tie. A cell wraps inside its column; its further lines keep its indent.
3. **The stacked form.** The table prints as records between rules of `─` across the whole width. The first record names the columns, the headers that are not empty joined by ` · `, so a folded column's count stays in view. Each row follows: the first cell on a line of its own, with its indent; then, indented two cells, one line `<head>: <cell>` for each further cell that is not empty, with further lines indented four cells. A run of centred columns shares one line, its pairs joined by ` · `, and breaks between pairs: `📝: 🟢 · 📌: 🧑`.

The box uses `┌ ┬ ┐`, `│`, `├ ┼ ┤`, `└ ┴ ┘` and `─`. A centred cell takes the smaller half of the spare cells on its left; a right-aligned cell takes them all on its left. One rule stands under the header. A rule parts the body rows only when some row holds more than one line and the first cells do not tell the rows apart, that is when a first cell is empty or wraps; a grid whose titles wrap therefore stays one line of rules shorter per row, since its Id column marks each row.

The centred columns are what the tight box and the stacked form key on, and the grid of both tableaux sets `doc.Centre` on its gate columns ([design a3cc](a3cc.md#the-grid-of-both-tableaux)). The writer knows no grid: a Marks column and a Symbol column take the same rules. Over the 123 golden cases at 80 cells the trial draws 365 tables: 143 padded, 173 tight, of which 165 wrap a cell, and 49 stacked, the provenance tables of five to seven columns among them. At 132 cells two stack.

### The command line (D4, D6, D7)

Two options join the vocabulary of design 5ca9, after `--text` and before `-o`; both apply to the ten views.

| Option                | Value and check                                                              | Help line                                                              |
|-----------------------|------------------------------------------------------------------------------|------------------------------------------------------------------------|
| `--width <n>`         | A whole number, 20 or more; needs `--text`; `--brief` excludes it            | With --text, wrap at \<n> cells: 20 or more, 80 by default             |
| `--selector <policy>` | `strip` or `keep`; needs `--text`; `--brief` excludes it                     | With --text, strip (the default) or keep U+FE0F after a narrow symbol  |

The usage errors read `--width applies to --text only`, `--selector applies to --text only`, `--width takes a whole number, 20 or more, not "<value>"`, `--selector takes strip or keep, not "<value>"` and `--brief excludes --width and --selector`.

**What the command passes.** With neither option it passes the zero `text.Options`, which the writer reads as 80 cells and `Strip`. It reads no `COLUMNS`, no `TERM_PROGRAM` and no terminal size, so the same command line gives the same bytes in a shell, in a pipe and in CI, as design 5ca9 states of every rendering. A user who wants the terminal's width writes `--width $COLUMNS`. A text rendering passes no link base: `Links` stays zero, so a task prints with no file link (R13: `""` writes no file link), and a reference prints its URL as the task file states it, an absolute URL or a path from the repository's root.

```go
// In package cli, which imports the writer's package as rtext, since the
// table keeps the name text.

// textFunc renders one view's data at one level as Unicode text.
type textFunc func(data any, level string, o rtext.Options) ([]byte, error)

// text maps a view to its text renderer: the ten views, by viaText.
var text map[string]textFunc

// viaText returns the text renderer of one view. It checks the data as
// viaRender does and calls render.Render with Format Text and no link.
func viaText[V view.View](name string, fits func(V) bool) textFunc

// draw is what viaRender and viaText share: the type check, the level,
// the recovery of a builder's panic, and the call of render.Render.
func draw[V view.View](name string, fits func(V) bool, data any, level string, o render.Options) ([]byte, error)

// invocation gains one field.
type invocation struct {
	Query  Query
	Text   bool          // --text; false is Markdown
	Draw   rtext.Options // --width and --selector; zero where absent
	Output string
	Viewer bool
}
```

Step 2 of the read flow changes: with `--brief`, `runRead` takes the `brief` entry of the `markdown` table under either format, since the brief is plain text and the same bytes under both ([design e4c7](e4c7.md), decision 1); otherwise it takes the view's entry of the table the format names, and calls a text entry with `inv.Draw`. A missing entry returns 2 with the message design 5ca9 gives.

**The closing command (D6).** R12 lists the flags of the canonical command and names no format, since Markdown is the default. Under `Format: Text`, `command` appends `--text` after `--level`, then `--width <n>` when `Options.Text.Width` is neither 0 nor 80, then `--selector keep` under `Keep`: each only when in force, in R12's own words. At provenance the command then reproduces the bytes, as R12 promises. The closing paragraph wraps as any other; the commands of a `Pre` do not.

### What the design keeps from the prototype

From [`prototype/e0f7`](../prototype/e0f7/README.md) it keeps the single-line box, the centred gate cells, the two-cell tree indent in the task column, the rule that the task column narrows first, and the model of the selector as a policy the caller states. It drops the hand-picked width table, the `narrow` policy, truncation with an ellipsis (a cell wraps, so the text keeps the Markdown's content), the `folded` footer line (the count stands in the column header, e3ed decision 5), `$COLUMNS`, and `-probe`. The prototype's five questions:

| Question                         | Answer                                                                                         |
|----------------------------------|------------------------------------------------------------------------------------------------|
| 1. The selector policy           | `strip` by default, `--selector keep` for a terminal that widens the pair (D1). The fourth option, symbols of emoji presentation only, is a recommendation for SYNTAX.md, as tablotui `679b` notes, and no renderer's to enforce |
| 2. The source of the width table | `golang.org/x/text/width` and the standard `unicode` package (D2)                              |
| 3. Below the minimum width       | The tight box, then the stacked form; never a line past the width (D3)                         |
| 4. Colour                        | None, and no flag for it: the format serves a log and a message. A later task may add styles; the writer's spans leave room |
| 5. The layout                    | Id first and left, symbols alone in the header with a key line beneath: the grid's builder already decides both (a3cc). Centred cells, the two-cell indent and no branch glyph, single-line boxes: kept. The fold count: in the header |

Where the texts are silent or differ:

- No text of the method defines the text format beyond the task description; VIEWS.md does not mention it. The forms above are this design's.
- Design e3ed says a `Link` may "drop or underline" and `Strong` likewise; plain text cannot underline, and D5 keeps both as marks.
- The task description says "sized to a terminal width". The command sizes to the width it is told, and probes none (5ca9 A14, A17).
- Under `Strip` the text prints `⚙` where the Markdown prints `⚙️`: one code point less, the same symbol.

**Findings.** The authority tree's `drawTree` (`internal/render/authority.go`, from c48a) pads its columns by the count of code points, so a title with a two-cell or a combining character shifts the Assignee column in Markdown and in text alike; the text writer prints the `Pre` as given and does not repair it. No view needs a builder of its own for text.

What the prototype's README reports of named terminals is its own account.

## Decisions at review

1. **The selector policy and its option.** `--selector strip|keep`, `strip` by default: the text prints `⚙` for `⚙️` so that every terminal counts one cell, and `keep` serves a terminal that widens the pair. The alternative makes `keep` the default, which keeps the emoji look and breaks the right border where a terminal counts by code point. A third policy and a default read from `TERM_PROGRAM` are dropped. Binds tablotui `679b` (decision 5, one rule for both tools) and `5ca9` (the vocabulary).
2. **The width table is a dependency.** `golang.org/x/text/width`, BSD-3-Clause, with the standard `unicode` package for the zero-width categories. The alternative is a table generated from Unicode's `EastAsianWidth.txt` and kept in the repository, which adds no module and a file to regenerate each year; `go-runewidth`, which tablotui links through `x/ansi`, costs 25 ms at every start. Binds `go.mod`.
3. **Below the width a table tightens, then wraps, then stacks.** No line runs past the width but a preformatted one. The alternatives are to print the table at its full width and let the terminal wrap it, or to drop the columns outside the window, which loses content the Markdown shows. At 80 cells 49 of the 365 tables of the golden cases stack, the widest provenance tables among them.
4. **`--width <n>`, 80 by default, and no reading of the terminal.** The same command line gives the same bytes everywhere, and a user who wants the terminal's width writes `--width $COLUMNS`. The alternative reads the terminal's size when standard output is one, which makes a rendering in a shell differ from the same command in a pipe and departs from 5ca9's determinism and its A17. Binds `5ca9`.
5. **Plain text, with marks for emphasis and links.** No escape sequence and no colour flag; `Strong` prints between asterisks, so the person in view stays marked (R5), and a link prints its target in angle brackets. The alternative drops both marks, as design e3ed allows, and loses R5's emphasis in the eight list views. Binds no other design.
6. **The closing command carries `--text`,** and `--width` and `--selector` when they depart from the defaults. This extends e3ed's R12, whose list of flags names no format. The alternative prints the Markdown's command under a text rendering, which reproduces the view and not the bytes. Binds `e3ed` (R12) and `c48a`, `a3cc`, `9167`, whose frames print the command.
7. **The text table has its own function type, and the brief has one entry.** A text renderer takes `text.Options` and no link base, and `--brief` reads the `markdown` table under either format. This amends 5ca9's A17 and its flow, and confirms e4c7's A11. The alternative keeps one signature and widens it for both tables with arguments each format ignores. Binds `5ca9` and `e4c7`.
