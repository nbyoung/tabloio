# Design 5ca9: Read commands

`tabloio` gains one subcommand per view. Each takes the parameters VIEWS.md gives that view, asks tablo for the view data, hands the data and a level to a renderer, and writes the bytes to standard output or to a file. No read command changes project state. Five choices shape the design: tabloio links tablo as a Go library and runs no `tablo` executable (D1); one vocabulary of options serves every command, with `--person` for the person (D2); the person defaults to the viewer on two views only (D3); `--level` alone fixes the level and defaults to `glance` (D4); and an option a view does not take is a usage error (D5). D*n* names decision *n* under [Decisions at review](#decisions-at-review).

The drafts under [`5ca9/`](5ca9/) fix what prose fixes badly; the implementation copies them to `internal/cli/testdata/`.

| [`5ca9/mockup-commands.tsv`](5ca9/mockup-commands.tsv) | Every command line the ten Markdown mockups show, with its verdict under this vocabulary |

## The model

### The command line

```
tabloio [-C <dir>] <command> [<operand>] [<options>]
```

Options stand anywhere on the line, before or after the command. The first word that is no option and no option's value names the command. An option takes its value as the next word, or after `=` when it takes exactly one value. `--` ends the options. A long option takes two hyphens; the single-letter options are `-C`, `-o` and `-h`. An unknown option, a repeated option, a missing value and a single-hyphen long option (`-ref`) are usage errors.

**The commands.** The names are the mockups' file names, and every mockup agrees on them. The order is VIEWS.md's.

| Command      | View                   | Options beyond the common ones                                  |
|--------------|------------------------|-----------------------------------------------------------------|
| `gates`      | Gate definition        | `--task`                                                        |
| `task <id>`  | Task definition        | `--person`                                                      |
| `authority`  | Authority delegation   | `--task` `--person` `--proposed`                                |
| `assignment` | Task assignment        | `--task` `--person`                                             |
| `queue`      | Contributor work queue | `--task` `--person` `--brief`                                   |
| `blockage`   | Work-blockage tree     | `--task` `--person`                                             |
| `tableau`    | Global tableau         | `--person` `--window` `--columns` `--historical`                |
| `context`    | Contextual tableau     | `--task` `--person` `--window` `--columns` `--historical`       |
| `history`    | History                | `--task` `--person`                                             |

**The vocabulary.** One spelling means one thing on every command. The last column is the option's line in a command's help.

| Option                | Applies to                     | Value and check                                                        | Help line                                                        |
|-----------------------|--------------------------------|------------------------------------------------------------------------|------------------------------------------------------------------|
| `-C <dir>`            | Every command                  | A directory; relative paths in other options resolve against it, as Git's `-C` | Run as if started in \<dir>; the project is the nearest .tableaux at or above it, as tablo's Loader finds it (decided at review, 4f60 decision 7) |
| `--ref <ref>`         | The ten views                  | Not empty. `<from>..<to>`, both sides present and no third dot, on `history` only | Read the project at this commit; history also takes \<from>..\<to> |
| `--level <level>`     | The ten views                  | `glance`, `detail` or `provenance`; `glance` when absent              | Write at glance (the default), detail or provenance              |
| `--markdown`          | The ten views                  | Excludes `--text`; the default                                         | Write Markdown (the default)                                     |
| `--text`              | The ten views                  | Excludes `--markdown`                                                  | Write Unicode text                                               |
| `-o`, `--output <file>` | The ten views                | A path, or `-` for standard output; no component is `.tableaux` or `.git` | Write to \<file>; - is standard output (the default)          |
| `--task <id>`         | All views but `task`, `tableau` | `^[0-9a-f]{4}$`, as the operand of `task`                             | Focus on one task, or on the subtree under it                    |
| `--person <email>`    | All views but `gates`          | `^[^\s@]+@[^\s@]+$`                                                    | Focus on one person                                              |
| `--window <n>`        | `tableau`, `context`           | A whole number, zero or more; excludes `--columns`                     | Show \<n> gate columns either side of the next gates in view     |
| `--columns <gates>`   | `tableau`, `context`           | Gate keys joined by commas, each `^[a-z][a-z0-9_-]*$`                  | Show these gate columns: gate keys joined by commas              |
| `--historical`        | `tableau`, `context`           |                                                                        | Show the marks of historical junctions                           |
| `--proposed`          | `authority`                    |                                                                        | Show proposed tasks only                                         |
| `--stale <days>`      | `audit`                        | A whole number, zero or more                                           | Take a status older than \<days> as stale                        |
| `--brief <id> <gate>` | `queue`                        | Two values: a task id and a gate key; excludes `--level` and `--task`  | Write one item as a brief                                        |
| `--json`              | `version`                      |                                                                        | Print the versions as JSON                                       |
| `-h`, `--help`        | Every command                  |                                                                        | Print this text                                                  |

Three further rules complete it. `context` takes `--task` or `--person`, not both. An option outside a command's row is a usage error that names the command (D5). tabloio checks spelling and shape only: whether a ref, a task or a gate exists is tablo's to say, since only tablo reads the project.

**What the vocabulary keeps and drops from the prototype.** It keeps one subcommand per view, the task id as an operand, options on either side of it, `--markdown` and `--text`, `-o`, `-C`, the range inside `--ref`, the checks before anything is read, and the strictness. It drops `--for` (D2); `--role` (D4); `--window` and `--columns` on the eight list-shaped views, by the owner's ruling; `--brief TASK:GATE` in favour of the two values the mockups and VIEWS.md write (D6); `--tablo` and `--testdata` with the executable they served (D1); and Go's `flag` package, which accepts `-ref` for `--ref`.

### The person and the level

**The person.** VIEWS.md gives `person` one default, the viewer, and the mockups show that it fits two views. The rule here: `queue`, and `context` without `--task`, take the viewer when `--person` is absent; on every other view an absent person means no person, so the view shows everyone and marks no one (D3). tabloio asks tablo for the viewer (A8) and names the person in every query, so tablo applies no default of its own. A queue with no `--person` and no email in Git's configuration is a usage error.

**The level.** `--level` fixes the one level a rendering holds, and `glance` is the default: tabloio writes for static media, and VIEWS.md opens every role at glance on a static export. The command takes no `--role` (D4). `--brief` writes the queue's provenance level for one item, so it excludes `--level`.

### tablo as a library

tabloio imports `github.com/nbyoung/tablo` and calls the function behind `tablo view` in its own process (D1). It runs no `tablo` executable for view data.

- **The release promise holds.** README.md says each binary "depends on nothing on the host but `git`". An executable on the path is a second dependency, and its version varies apart from tabloio's.
- **The pairing is fixed at build time.** `go.mod` already carries the policy for it, and `tabloio version --json` names the one tablo version that produced the data (1422 A9). With an executable, a check of the envelope's schema at each run replaces what the compiler checks once.
- **The renderers take typed data.** Prototype 5ca9 found that a decoded envelope loses key order. The renderers need tablo's Go types either way, so the executable adds a process, an encoding and a decoding, and removes no import.
- **The three front ends share one path.** The umbrella plan has `tablotui` and `tableaud` embed the library; the same call then serves all three, and tablo's Conformance task (4b4f) tests the command over it.
- **The price.** A fix in tablo's views reaches a user through a tabloio release. The dependency policy bounds it to one minor series, and both projects release from a tag. `validate` stays a command of tablo alone, as 1422 decides, and the Write commands decide for themselves how they reach `tablo trailer`.

The choice lives in one file. `internal/cli/source.go` is the only file that imports tablo, behind the `Source` interface below, so an owner who rules for the executable changes that file and nothing else.

The package is new; README.md's layout table gains its row with the implementation. It stays internal: `tablotui` reuses the write actions, which b618 exports, and nothing of the command line.

```go
package cli

// The exit codes of every tabloio command. They keep the meanings tablo's
// plumbing command gives them (prototype 4ed9).
const (
	ExitOK      = 0 // the command wrote what it was asked for
	ExitInvalid = 1 // an error diagnostic prevents the view; nothing is written
	ExitUsage   = 2 // the command line is wrong; nothing is read
	ExitFailure = 3 // a read, a rendering or a write fails
)

// Env carries what a command takes from the process, so that a test
// replaces each part.
type Env struct {
	Stdout, Stderr io.Writer
	Version        string // main.version, as GoReleaser sets it
	Source         Source
}

// Run parses argv, the arguments after the program name, runs the command
// they name and returns its exit code. It never calls os.Exit.
func Run(ctx context.Context, argv []string, env *Env) int

// Command is one subcommand. The read commands fill ten; the Write commands
// task adds its own to the same table.
type Command struct {
	Name     string
	Group    string   // "read", "write" or "other": the section of the usage text
	Operands string   // "<id>" for task, "" otherwise
	Summary  string   // the view's question, verbatim from VIEWS.md
	Options  []string // the option names it takes beyond -C and --help
	Run      func(ctx context.Context, env *Env, a *Args) int
}

// Option is one entry of the vocabulary.
type Option struct {
	Name   string // the key in Args, and the long spelling unless NoLong
	Short  byte   // 'C', 'o', 'h', or 0
	NoLong bool   // true for -C alone
	Arity  int    // the number of values: 0, 1 or 2
	Values string // "<dir>", "<id> <gate>": the help text's operand
	Help   string
}

// Args is a parsed command line: the command, its operands, and the values
// of each option given.
type Args struct {
	Command  string
	Operands []string
	Values   map[string][]string
}

// Parse splits argv by the rules of "The command line". It knows the
// vocabulary and no command; Run checks the options against the command.
func Parse(argv []string, vocabulary []Option) (*Args, error)

// Source gives view data. tabloSource calls tablo's library; a test gives
// a fake.
type Source interface {
	// View derives one view. It returns no Data only when an error
	// diagnostic prevents the view.
	View(ctx context.Context, q Query) (Result, error)
	// Viewer returns the email Git commits with in dir, or "" when Git has none.
	Viewer(ctx context.Context, dir string) (string, error)
}

// Query names one view and every parameter in force. A zero field means
// the parameter is not set.
type Query struct {
	Dir        string   // -C; "" is the current directory
	View       string   // the command's name: "gates" … "audit"
	Ref        string   // "" leaves tablo's default; "from..to" on history
	Task       string
	Person     string   // the --person value or the viewer; "" is no person
	Window     *int
	Columns    []string
	Historical bool
	Proposed   bool
	Stale      *int     // nil leaves tablo's default, seven days
	Brief      *Brief
	Level      string   // always set
}

// Brief names the one queue item a brief is written for.
type Brief struct{ Task, Gate string }

// Result is what tablo returns: the view's data in tablo's own type, and
// the diagnostics of the project.
type Result struct {
	Data        any
	Diagnostics []Diagnostic
}

// Diagnostic mirrors a diagnostic of tablo's envelope (1422 A5).
type Diagnostic struct {
	Severity, Code, Path string
	Line, Col            int
	Message              string
}

// renderFunc renders one view's data at one level. linkBase is the path
// from the directory the output lands in to the project directory, with
// forward slashes, and "" when they are the same.
type renderFunc func(data any, level string, linkBase string) ([]byte, error)

// markdown and text map a view to its renderer. The key "brief" holds the
// renderer of the Agent briefs task. text starts empty; the Text renderers
// task (e0f7) fills it.
var markdown, text map[string]renderFunc
```

Each entry of `markdown` is a closure of two or three lines that asserts the data's type and calls the function the accepted renderer design exports (A13). `tabloSource.View` maps the `Query` field by field onto the call the accepted 4ed9 design exports (A1). Both follow those designs' names; where a name differs from an assumption below, the accepted design wins and only that file changes.

### The flow of a read command

1. `Parse`, then the command's checks in the order of the vocabulary table. A failure prints `tabloio <command>: <message>` and `Run 'tabloio <command> --help' for its options.` on standard error and returns 2. The messages are those [`5ca9/cases.json`](5ca9/cases.json) names.
2. Choose the table by format and look the view up, or `brief`. A missing entry returns 2 with `the text format does not cover <view> yet`.
3. Resolve `--output` against `-C` and apply the guard.
4. Set `GIT_OPTIONAL_LOCKS=0` in the process environment, so that no `git` the library runs refreshes the index.
5. Where the person defaults to the viewer, call `Source.Viewer`; `""` returns 2 with `no person: give --person, or set user.email in Git`, and an error returns 3.
6. Call `Source.View`. An error prints `tabloio <command>: <error>` and returns 3.
7. With no `Data`, print each error diagnostic as `<path>:<line>:<col>: error <code>: <message>`, leaving out a zero position and an empty path, and return 1. With `Data`, ignore the diagnostics: they are `tablo validate`'s to report and the audit view's to show.
8. Render. An error returns 3.
9. Write the bytes as the renderer returns them, with nothing added: to standard output, or to the file through a temporary file in the same directory and a rename, mode 0644, so that a failure leaves an existing file as it stood. A write error returns 3.
10. Return 0. An empty view is an answer, not a failure.

**The link base.** A Markdown rendering links tasks to files in the repository, and a relative link resolves from where the file lands. On standard output the base is `""`. With `--output`, it is `filepath.Rel` from the output's directory to the project directory, with forward slashes and `"."` as `""`; when no relative path exists it is the project directory's absolute path.

**No change of project state.** Project state is the files under `.tableaux`, and the repository's objects, refs, index and configuration. tabloio itself writes one thing, the `--output` file, and the guard refuses a path with a `.tableaux` or `.git` component. It makes no commit and runs no `git` of its own; the library reads through `git` (A5), and step 4 stops Git's one habitual write, the index refresh. A trial confirms the mechanism: after `touch` on a tracked file, `git status` rewrites `.git/index`, and with `GIT_OPTIONAL_LOCKS=0` it leaves the file byte for byte (Git 2.47.3).

**Determinism.** The same files, history, viewer and command line give the same bytes. tabloio adds no time, no host name and no commit id. Two things outside the files can move the output, and both are stated: the viewer, on `queue` and `context` without `--person`; and the clock, if tablo measures a stale status against today (A11), on `audit`.

### `help` and `version`

`tabloio help`, `--help` or `-h` with no command prints [`5ca9/usage.txt`](5ca9/usage.txt) on standard output and returns 0; `tabloio` alone prints it on standard error and returns 2. The usage lists the commands by group, in table order, each as two spaces, the name and operand padded to 14 columns, and the summary; it leaves out a group with no command. The draft fixes the heading of the read group and of the other group; b618 words the heading of its own. `tabloio <command> --help` and `tabloio help <command>` print the form of [`5ca9/usage-tableau.txt`](5ca9/usage-tableau.txt): the usage line, the summary, then the common options and the command's own in the order of the vocabulary table, each as two spaces, the spelling padded to 23 columns, and the help line. `--help` anywhere before `--` wins over every other check.

`tabloio version` prints `tabloio <version>`, one line. `tabloio version --json` prints one line, with `tablo` as `"v"` joined to `tablo.Version` and `tableaux` from `tablo.AcceptedMajor` and `tablo.AcceptedMinor`:

```json
{"command":"version","data":{"tableaux":"0.3","tablo":"v0.1.0","tabloio":"0.2.0"},"diagnostics":[],"schema":"tabloio/1"}
```

## Conformance to the texts

Each command passes the parameters of its VIEWS.md section and no other; the renderer designs own the form of each level. The command line of every level is `tabloio <command> … --level <level>`, as the mockup states under it.

| Command      | VIEWS.md section       | Mockup          | Parameters passed                                              |
|--------------|------------------------|-----------------|----------------------------------------------------------------|
| `gates`      | Gate definition        | `gates.md`      | ref, task                                                      |
| `task`       | Task definition        | `task.md`       | task (required), ref, person                                   |
| `authority`  | Authority delegation   | `authority.md`  | task, person, ref, the proposed filter                         |
| `assignment` | Task assignment        | `assignment.md` | person, task, ref                                              |

## Implementation notes

**Order.** `args.go` with T1 to T3; `cli.go`, `version.go` and the help with T13 and T14; `read.go` and `output.go` against the fakes with T4 to T12; then `source.go` and `render.go`, once tablo tags a release with its views and the four renderer tasks land; then `main.go`, which builds the `Env` and passes a context that an interrupt cancels. The first three steps need neither tablo nor the renderers.

**Files.** The eight under [Packages](#packages), their tests, and `internal/cli/testdata/` with the four drafts. `cmd/tabloio/main.go` keeps `version` and `versionString`. `README.md` gains the `internal/cli/` row, and its two `--for` examples and its bare `--brief` take this vocabulary. `prototype/5ca9/` leaves with the implementation: its stand-in, its generic renderer and its testdata serve an executable and a data shape this design drops.

**Dependencies.** `github.com/nbyoung/tablo` (MIT), under the policy README.md states; this task or the Renderers adds the `require` line, whichever imports first. No other: the parser is some hundred lines, and a flag library would bring its own rules for `-ref`, for repeated options and for a two-value option.

**The plan.** Two entries are missing. `b618` Write commands enters the command table this task creates, so it needs `requires: { id: "5ca9", from: implementation, to: implementation }`, or the two tasks agree which lands `cli.go` first. And `5ca9` cannot pass integrate before tablo releases its views; the umbrella's requirement of `6103` on `77b2` says so for the project, and no entry says so for this task. The task's own description names "a role that selects the disclosure level" and "a gate window or a list of columns" without limit; D4 and the owner's ruling on the window change both.

## Decisions at review

The owner decided each question this design raised on 2026-10-06, together with the cross-design rulings of that review; a decision the review did not reach stands as the design states it, accepted with the design.

1. **Library or executable (1422 decision 4).** Decided by the owner on 2026-10-06: tabloio links tablo as a Go library, behind one interface in one file, as [tablo as a library](#tablo-as-a-library) states; the ruling binds every front end of the wave, and tablo's 4ed9 decision 1 states the same. The alternative ran `tablo <view> --json` and decoded the envelope: a tablo fix then needed no tabloio release, and every read command needed a second binary on the path. Binds 4ed9 (A1) and b618, whose `Source` becomes an in-process adapter.
2. **`--person`.** Decided by the owner on 2026-10-06: the person parameter is `--person` everywhere, with no `--for` alias. The nine mockup lines stay as drawn, and VIEWS.md's log records the ruling; both READMEs change now. Binds 4ed9 (A2), b618, e4c7, the renderers, and tableaud's Server (49ce) and templates, whose HTML query names follow the vocabulary (`task`, `person`, `ref`, `level`, `window`, `columns`, `historical`, `proposed`, `stale`). The alternative kept `--for`, as README.md wrote it.
3. **The default person.** Decided by the owner on 2026-10-06: the viewer on `queue` and on `context` without a task; no person elsewhere. tableaud's 49ce decision 7, which added `authority` and `task`, is withdrawn. VIEWS.md's parameter table gains the per-view default. Binds tablo's view tasks (A9), tablotui and tableaud.
4. **No `--role`; `glance` by default.** Decided by the owner on 2026-10-06: `--level` alone sets the level in tabloio, whose output is a file, and the command passes the level explicitly; tablo keeps `--role` and the role-based default for the live front ends (4ed9 decision 6). The task's description, which names a role, stays as authorised; this entry records the departure. The alternative derived the level from the viewer's role in tabloio too.
5. **Strictness.** Decided by the owner on 2026-10-06: an option a view does not take is a usage error. VIEWS.md, which said it has no effect, changes to agree. The alternative followed VIEWS.md and ignored it, so that one line of options served every view and `queue --window 0` succeeded while doing nothing.
6. **`--brief <id> <gate>`.** Accepted with the design, as stated: two values, as all 13 mockup lines and VIEWS.md write it. The alternative is one value, `<id>:<gate>`, which every flag library parses; README.md's bare `--brief` names no item and falls either way. Binds e4c7 (A19).
7. **Exit 1 means no view.** Accepted with the design, as stated: a read command returns 1 only when an error diagnostic prevents the view, and prints no diagnostic beside a view it does write. The alternative returns 1 on any error diagnostic, as tablo's prototype does, so that a clone without its submodules renders nothing at all.
8. **The output guard.** Accepted with the design, as stated: `--output` refuses a path inside `.tableaux` or `.git`. The alternative trusts the caller, and one mistyped path then overwrites a task file.
9. **No commit id, no flag for one.** Accepted with the design, as stated: this design amends 1422's A8 and adds no option that prints the commit in view or the time. The alternative adds `--stamp`, which a snapshot must never set.
10. **The dispatcher.** Accepted with the design, as stated: this task owns `cmd/tabloio/main.go` and the command table, and `tabloio` with no command prints the usage and returns 2 where it prints the version today. The alternative gives the table to b618. Binds b618 (A18), whose task file now requires this one from implementation to implementation, as [The plan](#implementation-notes) asked.
11. **Where the project is.** Decided by the owner on 2026-10-06, from the Loader's review (4f60 decision 7): `-C` names where the search starts, and the project is the nearest `.tableaux` at or above it, up to the repository's root; the command line table reads so. The alternative, which this design assumed, read the named directory alone.
12. **A view stands beside an error.** Recorded on 2026-10-07 from tablo's `27a3` and tablotui's `0afa` and `f394`, which the owner accepts that day. A4 is amended (`27a3` decision 6): tablo gives no view data only for what it cannot read, a missing or unaccepted version, an unusable `gates.yaml` and a broken tree; every other error diagnostic leaves the view standing beside it, so the command draws the view and reports the diagnostic. Decision 3, the person default, stands confirmed by both tablotui designs.
13. **What the text renderers ask of the read commands.** Recorded on 2026-10-07 from `e0f7`, which the owner accepts that day ([`e0f7`](e0f7.md), decisions 4 and 7). A17 is amended: a text renderer takes the data, the level, the link base and `text.Options`, so the `text` table has its own function type, and `--brief` reads the `markdown` table under either format. The vocabulary gains `--width <n>`, for `--text` alone, 80 by default; a width under 20, a value that is no whole number and `--width` beside `--brief` are usage errors with exit 2. It gains no selector. The command probes no terminal, as A17 states. Flow step 2 and T11 follow.
